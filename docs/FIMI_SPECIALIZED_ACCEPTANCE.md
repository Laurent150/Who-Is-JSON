# FIMI 1.2.0 小规模专项验收（2026-09-28）

## 结论

本轮未通过发布验收。交互能正常完成大部分请求，英文生成内容的语言一致性较好，但复核协议仍不稳定，且部分讲解稿与函数输入/输出存在影响理解的事实错误。不能把返回成功或自动测试通过当作解释准确率。

使用实际 FIMI 界面与已登录账户的 DeepSeek 试用链路。8 份样本、20 个配置组合，含两次人工定向重试共 22 次解释/讲解生成请求；18 次返回、4 次复核失败。20 个组合中有 18 个最终取得回复。没有收到试用额度耗尽提示，没有切换到其他付费配置。未读取余额或收费账单；这些数字不是总模型调用数，生成/复核以及自动语言识别可能增加底层调用。

## 发布前应修复的问题

### 1. 复核协议仍会使正常生成失败

4 次错误均为无效复核修改。已观测到不存在的 sections 路径、非数组 path，以及不存在的 nodes[17].explanation。复核严格校验阻止了无效修改，未把未复核草稿当成成功结果，但用户仍会遇到生成失败并承担已经发起的请求。

本轮增加规范数字字符串数组下标的兼容处理，例如 sections/"0"/text 与 sections/0/text 等价，只允许实际数组、已有字段和文字目标；拒绝 01、-0、越界、原型键与 id/位置修改。该改动通过正反例测试。第一条诊断没有保留未知键原值，不能证明它就是数字字符串；此改动后仍出现其他无效路径，因此不能宣称复核失败已经修复。下一步应统一/简化复核字段定位协议，并在严格校验下做有界的格式纠正，而不是忽略错误补丁。

### 2. 同步与异步的异常范围被混为一谈

node-jsonfile 中文非技术稿声称 fs.readFileSync 的读取错误不会进入只包住解析的 catch。实际 readFileSync 的 try 同时包含读取、stripBom 和 JSON.parse；只有 _readFile 的读取与 stripBom 在解析 try 外。

中文标准重点稿前文正确区分了两者，结尾却又概括“readFile 系列在 throws:false 时把读取或解析失败统一变成 null”。这对异步读取不成立。属于前后矛盾且影响失败行为理解的阻断错误。

### 3. 中文函数输入/输出遗漏异步边界

自编样本外层 async 函数实际返回 Promise<Map>；非法并发数使该 Promise 拒绝。两份中文 IO 都直接写返回 Map，并描述抛出 RangeError，缺少调用方收到 Promise 的关键区别。中文标准还要求读取价格为异步函数，但源码的 await 同样接受同步返回值。英文零基础对 Promise 和失败边界反而说明正确，表现随语言/模式变化。

### 4. 详细讲解稿会输出错误推演和未完成文字

Vue 英文详细稿声称 color:red 没有冒号，因此被跳过，显然与源码和字符串本身不符。随后出现“Wait, isObject should return true...”式自我纠正；Limits 章节又重复了错误推演。另有“四个函数”但实际列出五个的小计数问题。前两项为阻断，不能按普通措辞瑕疵放行。

## 语言一致性与风格

检查了 10 份成功返回的英文文本，未发现无关中文说明。中文标识符样本中出现的加载价格、编号列表、读取价格、并发数、成功、价格、错误均来自源码名称或字段，属于应保留原文。复核错误提示也正确使用英文。这个样本量不能证明任意情况下都不会混入中文。

发现英文工作台标题在未确定语言的阶段显示“Code snippet · 未确定”；Java 片段稍后识别为 Java，最终标题恢复英文。因此这是未确定/识别过渡状态的漏译，不是 Java 的最终语言标签错误。本轮已将显示标签经 i18n 转换，并补充 Unknown language 翻译及不改分析事实的回归测试。

风格开关有可见效果：两份英文详细稿分别约 6860/7923 字符，简短稿约 3338/3579 字符（含界面章节标签和术语注释，不是纯模型 token 数）。但零基础简短稿仍偏长，BOM、ESM 等术语和标识符密集；非技术读者的稿件也常逐句复述实现。详细稿更长不代表更准确。重点范围仍可能覆盖几乎全部函数，省略范围说明不明显。

其他条件准确性问题应修正：Vue 中文零基础稿把字符串值限制为“非空字符串”，源码没有该限制；中文标准稿把 truthy 缩成“布尔为真”；Day.js 将 !t.r 标题写成 absent，漏掉 0 等其他假值。段落稍长、术语选择偏硬可视为非阻断；改变实际条件的说法应与措辞问题分开。

## 本轮改动与验证边界

实际改动仅为复核数组下标的受限兼容、安全诊断细化、未确定语言标签翻译和相应测试，没有重写解释内容、修改语料期望值或改动用户源码。没有发布安装器。

本轮通过真实界面生成并查看函数 IO、步骤标题、多行选区、词语及讲解稿；最后两份源码与粘贴值逐字比较一致。生成失败保留源码和本地结构；两个测试页面未记录前端脚本错误。测试结束恢复开始时的代码、语言和解释模式，并关闭临时测试/登录回调页。

原始模型服务 JSON 没有从浏览器内部状态或凭据中提取。人工结论依据界面实际返回文本、步骤标题及少量服务端安全路径诊断；各分支的所有说明、全部知识卡、所有错误类型、跨设备云同步、原生安装包和长期稳定性没有穷尽验收。工作记录与组合清单位于忽略的本机验收目录；本报告保留可复现样本与设置及关键错误证据。本轮是实际平台试用链路，与此前自有 API 配置批量测试条件不完全相同，不直接合并成准确率。
