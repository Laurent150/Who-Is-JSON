# 局部改稿对照实验

本轮暂留步骤1—3，把步骤4的局部编辑作为候选方案，步骤5独立终审作为可测量的门控。候选方案尚未通过真实模型对照，不替换正式默认流程。

## 当前正确性门槛

按用户本轮要求，非硬错误不阻断继续测试。硬错误要求完整上下文下仍存在可指出的源码行为矛盾，例如且/或、控制流、返回结果、错误捕获、选区或函数身份讲错。正常返回段落不能只因使用“总是”就判为否认所有异常；不能仅靠违反已声明输入类型的值，把对正常输入的正确说明判错。明确把类型声明说成运行校验，仍算错误。

措辞歧义、冗长、术语解释不足保留为非阻断标签。输出未返回、格式拒绝、超长或网络失败单独记录可用性，不算正确回答。错语言另记语言合规情况，严重到不可用时单列，不混进源码事实准确率。本轮通过仅表示没有已确认硬错误，不代表零基础风格和完整产品验收均通过。

新旧输出必须用同一门槛重评；评分标准改变带来的通过数变化不是工程改进。原始严格评分、重新分类和原因均保留。人工阅读由当前助手完成，不能称为外部盲评；审稿模型自己的pass也不是正确性证据。

## 候选改动

- 复核返回字段编号、唯一原文片段、替换片段、源码引用及原因。程序验证引用、非重叠和字段范围，事务式应用；未选中的字符与结构保持不变。
- 复核输入保留原始源码、选区、冻结的语法证据和设置；不复用模型生成的事实笔记或重复的受众计划。中英文及点读/讲解稿各自的范围保留。
- 引用存在只证明出处，不证明语义正确。局部编辑也可能改错或漏改，必须实测。
- `evaluationReview`只能在本地实验环境显式启用；正式请求保持现有流程。关闭付费终审仍保留本地字段与长度校验，不伪造终审通过。
- 本次实验同时改变编辑提示及修改协议，结果只能归因于这套编辑方案；不能据此单独证明其中某一句提示或某个限制的作用。

## 第一轮固定对照

使用旧20份结果中的j1、j6、j17、j9：缓存返回条件、库存错误边界、语句点读类型边界，以及已接受的中文讲解稿。输入为保存的最终候选文字，包含j6在终审格式拒绝之前的候选。两种编辑器得到同一份原文，不重新生成笔记或草稿，也不把问题标签和参考答案交给模型。

每例旧/新各重复2次，交替顺序，共16次编辑请求。先运行一组旧/新，检查新增硬错误、格式和改动范围；有新硬错误或连续两次格式失败就暂停诊断，不自动跑完。首批重复保留全部结果，不择优。最多允许每项一次格式修复，并设全局4次修复上限。

对每份成功改稿另做一次现有终审，最多16次，用该原样候选对照“无终审时的可用结果”和“终审后的放行/拦截”，无需再次改稿。统计漏判、正确拦截、误拦、非硬问题拦截、协议失败、tokens和时延。额外终审是否有价值须由这些结果判断。

常规最多32次；连同有限格式修复最多36次新增模型请求。旧轮101/104计数独立保留，不挪用、不重置，也不把剩余3次当成新增授权。此计划不包含后续9例全量复验、原11例控制及未见样本；扩展前另定有上限的预算。

## 推进与停止

首次旧/新配对就做检查，发现新硬错误或格式反复失败立即停，分析后另存一个版本；不在冻结版本内边跑边改。若首批合格，再完成预定重复。首次小样本只能筛选是否值得继续，不能宣称普遍有效。

继续扩展至少要求候选没有新增硬错误、好样本未被改坏，且在存在硬错误的病例上有可复现改善。无改善则停止加量，定位提示/上下文/模型能力瓶颈。最多两轮有独立假设的候选编辑试验；第二轮须另行冻结和授权，不循环重试直到偶然通过。

后续才覆盖9个原失败配置、11个原接受配置，以及未用于修改的源码。它们必须覆盖中英文、两种点读阅读模式、三类讲解稿受众；在这些检查完成前，不宣称所有模式已验收。

该实验不部署云端、不构建安装包，不执行测试源码。
